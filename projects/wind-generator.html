Test limitation

Pushing the Limits of Large Scale Airflow Testing

Morphing wing actuation simultaneously affects roll, pitch, lift, drag, and stability. Repeatable inflow was required to isolate those effects, but The SMART Hawk's 1.2 m span exceeded the test section width of CSUN's available wind tunnels.

Developed an open air modular fan array to remove fixed test section constraints, then implemented independent motor control to balance velocity across the complete flow field.

System development

2 hardware and control architectures

Evolved the system from a 3 module, single controller prototype into a 5 module platform with distributed computation, 10 independent motor channels, and software defined airflow control.

Generation 01

3 module prototype with centralized control

3 fan modules in a shared flow path, each with 2 contra rotating motors on their own ESCs — 6 motors, 3 independent 400 W supplies at 24 V, about 1.2 kW total. A single Arduino R4 hosted the dashboard and generated all PWM outputs. Replacing binary fan commands with continuous PWM enabled adjustable airflow velocity and module level balancing.

Control

Per module trim with enforced command limits

Modules never produce identical flow, so each one carries a signed trim offset on top of the master setpoint:

Peffective = Psetpoint + Ptrim  ≤  100%

The interface enforces the command limit: applying +12% trim to a module and the maximum selectable setpoint drops to 88%, so the array cannot exceed 100%. These offsets provide the current method for balancing airflow between modules.

Safety controls
  • Implemented a global emergency shutdown that sets the master command and all electronic speed controller outputs to 0.
  • Added an independent physical power cutoff adjacent to the test system.
  • Established a common electrical reference across power supplies and controllers to maintain stable PWM signaling under load.
Generation 02

5 module platform with distributed computation

Expanded the array from 3 to 5 modules and from 6 to 10 independently controlled motors. Divided the control architecture between an NVIDIA Jetson Orin Nano, which manages the interface, telemetry, airflow pattern generation, and future AI assisted features, and an Arduino Pico P4 dedicated to clean PWM generation for the electronic speed controllers. The interface above runs on the Jetson — providing independent motor commands, telemetry, and steady operation control. Software defined configuration eliminated control changes through rewiring. Multiple high output 12 V supplies accommodate transient current demand from 10 high kV motors and prevent electronic speed controller desynchronization.

Instrumentation support

Anemometer wiring wizard

Developed a browser based wiring tool to standardize anemometer integration for closed loop airflow control. Users assign Hall signal, temperature signal, supply, and ground conductors directly on an interactive UNO R4 WiFi pin diagram.

Stores assignments locally, restores previous configurations, detects pin conflicts, and identifies prohibited connections to reduce harness assembly errors.

Mechanical fabrication

Manual fabrication of custom steel components

Fabricated small steel components by hand using a bench grinder, controlling final geometry through incremental material removal and dimensional checks between passes.

Validated capabilities
  • Continuous PWM control across all modules, with master and individual commands over a 0–100% range.
  • Module trim balancing with a software enforced 100% output ceiling.
  • Browser based operation and emergency shutdown, supplemented by an independent physical cutoff.
  • Data acquisition through spreadsheet compatible exports and JSON telemetry files.
Development in progress
  • Calibrate anemometers through curve fitting and signal noise filtering.
  • Calibrate the Pitot system and implement pressure to velocity conversion.
  • Automate module trim calibration to replace manual balancing.
  • Close the airflow control loop using anemometer and Pitot feedback.

Current operation is open loop; manual trim balances module output and a standalone anemometer verifies velocity.

Engineering contribution

Led both the physical expansion and control system redesign.

Control system. Replaced the single controller architecture with a Pico P4 dedicated to PWM generation and an NVIDIA Jetson Orin Nano for the interface, telemetry, and airflow pattern control. This separated time critical motor commands from higher level software and eliminated hardware rewiring for control changes.

Physical expansion. Led the expansion from 3 to 5 modules, increasing the system from 6 to 10 motors and extending airflow coverage from a wing section to the complete 1.2 m aircraft.
