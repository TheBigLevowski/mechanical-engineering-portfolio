Test limitation

Pushing the Limits of Large Scale Airflow Testing

Wing morphing changes roll, pitch, lift, drag, and stability at the same time. Studying those effects requires repeatable airflow, but The SMART Hawk's 1.2 m span exceeded the width of CSUN's available wind tunnels.

Built an open air modular fan array to extend testing beyond a fixed tunnel section. Independent motor control allows airflow velocity to be balanced across the full test area.

System development

Building the System Through 2 Generations

Expanded a 3 module prototype running on a single controller into a 5 module system with 10 independent motor channels. The updated design divides computing tasks between controllers and makes airflow control configurable through software.

Generation 01

Starting With 3 Modules and a Single Controller

The prototype placed 3 fan modules in a shared flow path, each with 2 contra rotating motors and separate ESCs. The 6 motors ran on 3 independent 400 W supplies at 24 V, totaling about 1.2 kW. A single Arduino R4 hosted the dashboard and generated all PWM outputs. Continuous PWM replaced on or off commands, allowing airflow speed and module balance to be adjusted.

Control

Balancing Each Module Within the Output Limit

Each module produces slightly different airflow. A positive or negative trim offset adjusts its command relative to the master setpoint:

Peffective = Psetpoint + Ptrim  ≤  100%

The interface keeps every command within 100%. Adding +12% trim to a module lowers the maximum selectable setpoint to 88%. These trim offsets currently provide manual airflow balancing between modules.

Safety controls
  • Added a global emergency shutdown that sets the master command and every electronic speed controller output to 0.
  • Installed an independent physical power cutoff beside the test system.
  • Connected the power supplies and controllers to a common electrical reference to keep PWM signals stable under load.
Generation 02

Expanding to 5 Modules With Dedicated Motor Control

Expanded the array from 3 to 5 modules and from 6 to 10 independently controlled motors. An NVIDIA Jetson Orin Nano handles the interface, telemetry, and airflow patterns, with support planned for AI assisted features. An Arduino Pico P4 focuses on generating clean PWM signals for the electronic speed controllers. The dashboard above runs on the Jetson and provides independent motor commands, telemetry, and steady operation control. Software settings allow control changes without rewiring. Multiple high output 12 V supplies handle current spikes from the 10 high kV motors and keep the electronic speed controllers synchronized.

Instrumentation support

Making Anemometer Wiring Easier to Check

Built a browser based wiring tool to guide anemometer connections for closed loop airflow control. Users assign Hall signal, temperature signal, supply, and ground wires directly on an interactive UNO R4 WiFi pin diagram.

The tool saves assignments locally, restores previous setups, flags pin conflicts, and identifies connections to avoid, helping users catch wiring errors during harness assembly.

Mechanical fabrication

Shaping Custom Steel Parts by Hand

Made small steel components with a bench grinder, removing material in stages and checking dimensions between passes to reach the required shape.

Validated capabilities
  • Continuous PWM control across all modules, with master and individual commands adjustable from 0 to 100%.
  • Module trim balancing with software that keeps every output within 100%.
  • Browser based operation and emergency shutdown, backed by an independent physical power cutoff.
  • Data acquisition with spreadsheet compatible exports and telemetry saved as JSON files.
Development in progress
  • Calibrate the anemometers using fitted response curves and signal noise filtering.
  • Calibrate the Pitot system and convert pressure readings into airflow velocity.
  • Automate trim calibration so the system can balance module airflow without manual adjustment.
  • Use anemometer and Pitot feedback to adjust airflow through closed loop control.

The system currently runs in open loop. Manual trim balances module output, and a standalone anemometer checks airflow velocity.

Engineering contribution

Led the expansion of the fan array and the redesign of its control system.

Control system. Replaced the single controller with a Pico P4 for PWM generation and an NVIDIA Jetson Orin Nano for the interface, telemetry, and airflow patterns. Dedicated PWM hardware keeps motor timing separate from higher level software, while software settings allow control changes without rewiring.

Physical expansion. Expanded the system from 3 to 5 modules and from 6 to 10 motors, extending airflow coverage from a wing section to the full 1.2 m aircraft.
